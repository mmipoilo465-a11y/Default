# Онлайн-запись для автосервиса и детейлинга

Одно приложение обслуживает сразу много студий. У каждой своя ссылка `https://ваш-домен/<студия>/`, своя иконка, свои цены и свой кабинет владельца.

- **Клиент**: открывает ссылку на телефоне или компьютере, выбирает услугу, день и время, оставляет имя и телефон. Регистрация не нужна. Приложение можно добавить на главный экран: оно открывается без адресной строки и со своей иконкой.
- **Напоминание за сутки**: после записи клиенту предлагается включить push-уведомление. Если уведомления недоступны (iPhone без установки на экран, запрет в браузере), вместо них появляются кнопки «Календарь iPhone / .ics» и «Google Календарь» с напоминанием за сутки.
- **Помощник клиента**: отвечает на вопросы вроде «Когда ближайшее окно?», «Сколько стоит полировка?», «Как найти студию?» по данным именно этой студии. Если не хватает данных (например, не названа услуга), задаёт уточняющий вопрос с кнопками.
- **Кабинет владельца**: `https://ваш-домен/<студия>/admin`, вход по почте и паролю. Там записи на день и неделю, заезды, завершённые работы, полученные деньги, ручная запись, перенос, отмена, статусы «Принята / Готова», оплаты и возвраты, все настройки студии, фото работ и помощник владельца («Что у меня завтра?», «Сколько машин было на неделе?», «Сколько денег получено?»).

Внешних зависимостей нет. Нужен только **Node.js 22.5+**: база данных SQLite встроена в Node.

---

## Запуск

```bash
npm start                 # http://localhost:3000/studio/ и /garage77/
npm test                  # расчёт слотов, разбор фраз, push, изоляция студий, защита
```

При первом запуске в `data/studios/` копируются две примерные студии:

| Студия | Ссылка | Кабинет | Пароль |
|---|---|---|---|
| Детейлинг «Ваша студия» | `/studio/` | owner@studio.ru | `Start-2026` |
| Автосервис «Гараж 77» | `/garage77/` | owner@garage77.ru | `Start-2026` |

## Новая студия за 5 минут

```bash
# 1. Создать студию (копия примера «Ваша студия» с новым названием). Скрипт напечатает пароль владельца.
npm run new-studio -- shine-spb "Shine Detailing" owner@shine.ru --from studio \
     --phone "+7 921 000-00-00" --city "Санкт-Петербург" --address "ул. Савушкина, 12" --accent "#3DDCFF"

# 2. Поправить цены, график и карточки в одном файле:
#    data/studios/shine-spb.json        (сервер подхватит изменения без перезапуска)

# 3. Фото, логотип и подписи к работам проще загрузить через кабинет:
#    https://ваш-домен/shine-spb/admin

# 4. (необязательно) Заполнить кабинет демо-записями для показа владельцу, а потом очистить:
npm run demo-data -- shine-spb
npm run demo-data -- shine-spb --clear
```

Владельцу отправляете две вещи: ссылку `https://ваш-домен/shine-spb/` и данные для входа в `/shine-spb/admin`. Сменить пароль: `npm run set-password -- shine-spb` (или сам владелец в кабинете, раздел «Доступ»).

Пароль можно записать прямо в файл: `"owner": { "email": "...", "password": "мой-пароль" }`. При первом чтении сервер заменит его на хэш.

## Где что хранится

```
data/
  studios/<студия>.json   ← ВСЕ настройки студии: название, услуги, цены, боксы, график, адрес, фото, карточки, вход владельца
  media/<студия>/         ← загруженные владельцем фото и логотип
  db/<студия>.db          ← записи и оплаты — у каждой студии свой файл
  system.db               ← хэши сессий владельцев и ключи уведомлений
  backups/                ← ежедневные копии
```

Для резервной копии достаточно сохранить папку `data/`.

### Поля файла студии

| Поле | Что это |
|---|---|
| `name`, `kind`, `tagline` | Название, тип («Детейлинг-студия»), слоган на главной |
| `city`, `address`, `howToFind`, `mapUrl` | Адрес и как заехать. Без `mapUrl` ссылки на Яндекс и 2ГИС строятся по адресу |
| `phone`, `telegram`, `whatsapp`, `paymentInfo` | Контакты и условия оплаты (их тоже использует помощник) |
| `theme.accent` | Фирменный цвет (`#C8FF2E`), из него же собирается иконка, если нет логотипа |
| `logo`, `hero` | Логотип и главное фото (путь `/media/...` или полная ссылка) |
| `cards` | Три информационные карточки `{title, text}` |
| `gallery` | Фото работ `{id, image, caption}` |
| `schedule` | Часы по дням: `"mon": ["09:00","21:00"]`, `null` означает выходной |
| `daysOff`, `specialDays` | Праздники `["2026-12-31"]` и особые часы `{"2026-12-30": ["10:00","16:00"]}` |
| `boxes` | Боксы `{id, name, active}`: каждый принимает одну машину |
| `services` | Услуги: `name, category, price, priceFrom, durationMin` **или** `days`, `boxes` (в каких боксах делается), `description`, `keywords` (слова для помощника), `popular`, `hidden` |
| `booking` | `bufferMinutes` (подготовка между машинами), `stepMinutes`, `minLeadMinutes`, `horizonDays` |
| `assistant.examples` | Свои кнопки-подсказки помощника (иначе подбираются сами) |

### Как считается свободное время

- Время начала проверяется по реальному графику дня (выходные, праздники и особые часы учтены).
- Работа в часах (`durationMin`) должна закончиться в тот же день, если укладывается в рабочий день. Более длинная продолжается со следующего утра.
- Работа в днях (`days`) начинается с открытия и занимает бокс до закрытия последнего рабочего дня, **включая ночи**. Выходные внутри срока не считаются рабочими днями. Пример: керамика на 2 дня, сданная в субботу, будет готова в понедельник вечером.
- После каждой машины бокс занят ещё на `bufferMinutes`. Если работа закончилась к закрытию, подготовка переносится на утро.
- Слот свободен, если хотя бы один подходящий бокс свободен всё это время. Отменённые записи бокс не держат.

## Размещение в интернете (получить ссылку)

Нужен небольшой сервер (VPS) — **лучше в России**: по закону 152-ФЗ персональные данные клиентов из РФ должны храниться на российских серверах. Подойдёт любой: Timeweb Cloud, Selectel, REG.RU, Яндекс Облако — тариф с 1 ГБ памяти и Ubuntu 22/24, это около 200–400 ₽ в месяц.

1. Арендуйте сервер с Ubuntu. Провайдер пришлёт IP-адрес и пароль.
2. Подключитесь к нему (в панели провайдера обычно есть кнопка «Консоль»).
3. Выполните три команды:
   ```bash
   git clone -b zapis --single-branch https://github.com/mmipoilo465-a11y/default.git zapis && cd zapis
   SEED_EXAMPLES=1 bash deploy/install.sh
   cat data/initial-passwords.txt
   ```
4. Скрипт напечатает ссылку вида `https://89-23-11-5.sslip.io/` — она уже с HTTPS, свой домен не обязателен.
   Для своего домена: направьте A-запись домена на IP сервера и запустите `bash deploy/install.sh zapis.вашдомен.ru`.

Новая студия на сервере:
```bash
docker compose exec app node scripts/new-studio.js shine-spb "Shine Detailing" owner@shine.ru --from studio
```
Файлы студий лежат в `data/studios/` на сервере; правки подхватываются сразу.

Переменные окружения (в `docker-compose.yml`):

| Переменная | Зачем |
|---|---|
| `NODE_ENV=production` | Рабочий режим: примеры с демо-паролями не создаются |
| `SEED_EXAMPLES=1` | Создать два примера со **случайными** паролями (файл `data/initial-passwords.txt`) |
| `TRUST_PROXY=1` | Приложение стоит за Caddy/nginx — доверять заголовкам X-Forwarded-* |
| `VAPID_SUBJECT` | `mailto:ваша@почта` для push-сервисов |
| `ANTHROPIC_API_KEY` | Необязательно: помощник отвечает на нестандартные вопросы через языковую модель (данные клиентов туда не передаются) |
| `BACKUP_KEEP_DAYS` | Сколько дней хранить резервные копии (по умолчанию 14) |
| `SHOW_INDEX=1` | Показать список студий на главной домена (по умолчанию скрыт) |

## Конфиденциальность и защита данных

**Студии не видят друг друга.** У каждой студии свой файл базы `data/db/<студия>.db`; записи, платежи и клиенты разных студий физически лежат в разных файлах. Кабинет пускает только по почте и паролю своей студии; cookie действует только на адресе этой студии. Автотесты (`npm test`) проверяют, что владелец одной студии не может прочитать или изменить записи другой — ни через подмену cookie, ни по номеру записи, ни через выгрузку.

**Клиенту не нужна регистрация.** Его записи на устройстве хранятся только в браузере (и стираются кнопкой в «Моих записях»); на сервере запись открывается по длинному случайному токену.

**152-ФЗ, что уже сделано:**
- согласие на обработку данных — обязательная галочка при записи, время согласия сохраняется;
- у каждой студии страница `/<студия>/privacy` с политикой; реквизиты оператора (ИП/юрлицо, ИНН, почта) и срок хранения владелец задаёт в кабинете → «Данные клиентов»;
- собираются только имя, телефон, авто и комментарий; рекламных счётчиков нет, шрифты и скрипты — со своего сервера;
- через заданный срок (по умолчанию 365 дней после визита) имя, телефон, авто и комментарий стираются автоматически, суммы остаются для отчётов; подписки на уведомления удаляются после визита;
- клиент сам удаляет свои данные из прошедшей/отменённой записи; владелец находит клиента по телефону и стирает его данные по запросу; есть выгрузка записей в CSV.

Что остаётся за владельцем студии: при необходимости уведомить Роскомнадзор о начале обработки персональных данных и разместить сервер в РФ. Это не юридическая консультация — для своего случая уточните у юриста.

**Защита:** пароли — scrypt; сессии в базе хранятся только хэшами, живут 30 дней, сбрасываются при смене пароля; cookie `HttpOnly; SameSite=Strict; Secure`; ограничение попыток входа и записи; запросы, изменяющие данные, принимаются только как JSON и только со своего адреса; заголовки CSP (только свои скрипты), запрет встраивания в чужие сайты, nosniff, HSTS; загружаемые фото проверяются по содержимому; кабинет и API закрыты от поисковиков; ежедневные резервные копии каждой студии в `data/backups/` (14 дней).

## Что внутри

```
server.js            HTTP-сервер и API
core/                расчёт слотов, время, статистика, календарь (общие для сервера и браузера)
lib/                 база, студии, записи, помощники, разбор русских фраз, web push, генерация иконок
public/              интерфейс клиента (app.*), кабинет (admin.*), service worker, шрифты
studios/             шаблон и примеры студий
scripts/             new-studio, set-password, demo-data
tests/               npm test
```
